# Keeping the docs in sync

The docs site (`docs/`, built with Material for MkDocs) and the README describe behaviour in detail, so most code
changes touch at least one page. Work through the map below for the change at hand, then run the checks.

## What to update for which change

| Change in the code                                | Update                                                                                                                                         |
|---------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------|
| New or changed CLI option, help text, exit code   | `cli.py` only for the reference (`docs/reference/cli.md` is generated by `docs/hooks.py`); the guide page that covers the feature              |
| New environment variable                          | `docs/reference/environment.md`; `docs/guide/scanner-containers.md` (Settings table) for `WIMI_SCANNER_*`; the `--help` epilog in `cli.py`     |
| JSON field or CSV column                          | `docs/reports/data-exports.md`                                                                                                                 |
| HTML report section or bottom-line wording        | `docs/reports/html-report.md`; regenerate `docs/sample-report.html` if the change is visible                                                   |
| Package ecosystem, image format, registry support | `docs/concepts/supported.md`, `docs/concepts/limitations.md`, `docs/concepts/how-it-works.md`                                                  |
| Base matching, catalog, estimated boundary        | `docs/guide/base-images.md`, `docs/guide/catalog.md`, `docs/concepts/how-it-works.md`                                                          |
| Vulnerability import, scanners, sidecars          | `docs/guide/vulnerabilities.md`, `docs/guide/scanner-containers.md`                                                                            |
| `--fail-on` rules                                 | `docs/ci/index.md` (rules table and the "data is missing" list), the `--help` epilog, `whats_in_my_image/policy.py` docstrings                 |
| Install, image, wrapper, compose                  | `README.md`, `docs/index.md`, `docs/getting-started/installation.md`, `contrib/` header comments                                               |
| CI workflow, required check, release step         | `docs/developer/index.md`, `docs/developer/releasing.md`, `docs/developer/branch-protection.md`, `SECURITY.md` ("How this project is checked") |
| Anything user-visible                             | `CHANGELOG.md` under `## [Unreleased]`                                                                                                         |
| A roadmap item done                               | Tick it in `ROADMAP.md`                                                                                                                        |

The README duplicates the docs home page's pitch, sample output and quick start. Change both together.

## Writing rules

- Tables are aligned: padded cells, `|----|` separators, equal widths. After editing a table, run
  `python3 .claude/skills/docs-sync/align_tables.py FILE...`.
- Wrap prose at about 120 characters. Use admonitions (`!!! tip`, `!!! warning`) the way the existing pages do.
- Link issues as `[#N](https://github.com/willj4945/whats_in_my_image/issues/N)` in `CHANGELOG.md` and `ROADMAP.md`
  (they are included into the docs site, where bare `#N` doesn't link).
- Don't claim support that isn't there. If a feature is partial, say what works and link the issue.
- CHANGELOG entries describe the user-visible effect, in Keep a Changelog sections (Added, Changed, Fixed, Security),
  under `## [Unreleased]` only.

## Checks

```bash
.venv-docs/bin/mkdocs build --strict -d /tmp/wimi-site; echo "exit=$?"   # broken links and nav fail the build
.venv/bin/wimi --help >/dev/null                                         # the reference page is built from this
git diff --stat
```

After merging `main` into a branch, confirm every new CHANGELOG entry is still under `## [Unreleased]`: a merge can
place it in an already-released section.

## Auditing for drift

When asked to review the docs, compare them with the code, not with each other:

1. `wimi --help` and each `wimi catalog <cmd> --help` against `docs/guide/*.md` and `docs/reference/`.
2. A real report's JSON keys and CSV headers against `docs/reports/data-exports.md`:
   `wimi docker:IMAGE -o /tmp/r -q` then list the keys.
3. Environment variables read in the code (`grep -rn environ whats_in_my_image/`) against
   `docs/reference/environment.md`.
4. Feature claims (`docs/concepts/supported.md`, README features) against the testbed images.
5. Repository settings named in `ROADMAP.md` ("Now") against `gh api repos/willj4945/whats_in_my_image`.

Report findings grouped as *inaccurate*, *missing* and *already accurate*, then fix them in one docs PR.
